# QoreLens origin audit

Scope is the frozen product at `v1.0.0` and the documentation checkout on
`master`. Git history, saved host evidence and the original Pages archive
were inspected read-only. Tests were inventoried from source and saved runs.
The audit did not run them again.

## Scaffold verdict

**PASS for actual generator use in Phase 0 recovery.** The first attempt in
`feasibility/evidence/00-scaffold.txt` failed at npm discovery and did not
scaffold anything. The later `00-scaffold-recovery.txt` records
`create-qorechain-dapp` **0.12.0**, Foundry template, Diana testnet selection,
npm, skipped prompts, and successful creation. `00-scaffold-run-output.txt`
corroborates the success. `host-scaffold-help.txt` describes the Foundry
template and its EVM authorization-window helper.

Working directory was `C:\dev\qorelens\feasibility\toolchain\scaffold`.
The following is the actual invocation with Windows path quoting. The
transcript renders its arguments with JSON escaping.

```powershell
node "C:\dev\qorelens\feasibility\toolchain\node_modules\create-qorechain-dapp\dist\index.js" "qorelens" "--template" "foundry" "--network" "testnet" "--package-manager" "npm" "--yes" "--no-install"
```

The generator output is under `feasibility/toolchain/scaffold/qorelens/`.
Generated files observed there include `foundry.toml`, `README.md`,
`package.json`, `tsconfig.json`, `.env.example`, `src/Counter.sol`,
`test/Counter.t.sol`, `script/Counter.s.sol`, and `scripts/window.ts`.
No environment-file contents are included in this audit. The project’s
`feasibility/toolchain/deploy-host.mjs` explicitly selects the generated
`scripts/window.ts` helper for the deployment preparation, backed by the
saved window status, registration and opening transcripts. The root
`foundry.toml` has different paths and compiler settings from the generator
output. No generated scaffold path is tracked, and the generated code and
configuration inspected are distinct from the tracked product files.
The evidence supports generator and helper use for feasibility and deployment
preparation. It does not establish that the product repository was emitted by
the generator.

identifies the [upstream qoresign-v1.json](https://github.com/qorechain/qoresign/blob/main/vectors/qoresign-v1.json)
as generated by the QoreSign TypeScript implementation. The locally saved
upstream file is `feasibility/evidence/qoresign-v1.json`. Comparing parsed data
against `test/vectors/public-vectors.json` gave 21 omitted paths, zero new
paths and zero changed values among retained fields. Omissions include the
mnemonic, private-key field, and unneeded transaction fields. The tracked
feasibility subset is a separate representation. The frozen product vector
blob matches the original Pages manifest SHA-256
`8444b1c39b5f`.
Hashing the Windows checkout can differ because Git materializes CRLF;
this comparison uses the Git blob and deployed asset bytes.

The host clone matched the saved raw vector bytes at `efe0f85d27cf`. Its LICENSE is Apache-2.0 and its NOTICE records Copyright 2026 QoreChain Association. The [notices](../THIRD_PARTY_NOTICES.md) reproduce both. The original download used unpinned main. The matching revision establishes content equivalence, not definitive historical HEAD provenance.

## Submission review gaps

- Vector attribution is documented from the exact byte-matching revision. The original unpinned acquisition limits historical HEAD claims.
- The frozen Pages archive contains IBM Plex WOFF2 files plus the bundled JS.
  The archive listing contains no separate license or third-party notice files,
  although the installed font packages include LICENSE files. The initial text search missed retained MIT headers, now identified by a direct scan of the bundled license blocks. Review
  redistribution notices for the fonts and bundled libraries. No claim of
  license compliance is made from lockfile metadata alone.
- The [Developer Fest rules](https://build.qorechain.io/rules) require credit
  for libraries, kits and templates in the README. The README credits the
  scaffold and names the relevant integrations, but does not currently
  enumerate the third-party vector and library sources. This audit makes no
  README changes.
- The host log verifies PR closure. Fresh post-cleanup ref and live Pages checks remain unavailable in this environment.
